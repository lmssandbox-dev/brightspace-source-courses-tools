## Version and lifecycle evidence

The native version-check contract is documented by [D2L API Properties](https://docs.valence.desire2learn.com/res/apiprop.html) and [API versions](https://docs.valence.desire2learn.com/basic/version.html). D2L defines product support and component version support separately. A higher latest version does not make a currently supported version deprecated. The checked-in lifecycle snapshot was reviewed 2026-10-11 against [D2L component lifecycle bands](https://docs.valence.desire2learn.com/about.html): LP 1.49+ / LE 1.82+ are listed as oldest fully supported; LP 1.46–1.48 / LE 1.75–1.81 deprecated; LP 1.45 and older / LE 1.74 and older obsolete. No EOL band was separately verified in that component table. D2L’s versioning guidance says deprecated versions have reduced support, obsolete versions may be removed, and EOL contracts are removed. Lifecycle evidence older than 365 days is marked stale and treated as unknown. The application does not scrape docs or detect future changes automatically.

Native checks verify whether the tenant supports configured component versions and report the tenant’s latest version. They do not validate individual endpoint routes, permissions, payloads, response JSON contracts, feature semantics, or user/service-user access. Thirteen contracts are marked Verified after route, method and relevant request/response details were reviewed in the cited official D2L pages: org-structure and org-unit-type list/detail/parents, parent add/remove, organization info, Source Course creation, course detail GET and course status PUT, and the three version-check routes. Sixteen Valence route contracts remain Not Verified; their source-derived summaries do not imply compatibility or contract review. The external dataset URL is Not Applicable. Verified route minima are recorded only where the D2L reference establishes them. Never upgrade production versions automatically; review and test changes first.

## Maintenance rule

Whenever an API call, endpoint path/method, configured API version, minimum-version guard, or request/response contract changes, update `src/apiHealth/endpoints.json`, `API_ENDPOINTS.md`, `AGENTS.md`, relevant subsystem docs, and endpoint coverage/contract tests. Store contract status, verification date, summary, and official source URLs in structured inventory fields. A documentation link by itself does not make a contract Verified. Keep route minimums, endpoint-specific risks, and lifecycle claims tied to official D2L sources and a verification date.
